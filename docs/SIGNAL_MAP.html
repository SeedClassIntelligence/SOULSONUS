What "Working" means here — and what it used to miss

Every row below describes main at the commit named above, which is the commit Netlify builds. That distinction matters: for most of this project's life the map described a feature branch that had never been merged, so it reported components as working while the deployed site was white-screening on a missing import from before the audit began. The status of a room and the status of the site are different questions, and this map only answers the second one when the two are the same commit.

If the rows here disagree with what you see on the live site, check that first — git log --oneline -1 origin/main against the commit in the header. The stamp names the last code commit the rows describe; this document is committed immediately after it, so the deployed head is normally one commit further on and contains no code the map has not seen.

19% of src/ is not reachable from the app the browser loads

Measured rather than sampled. scripts/dsp/reachability.cjs walks the import graph from src/main.tsx — the file index.html actually requests — and reports what never gets pulled in: 25 of 135 files, 7,248 lines. Three separate times a row in this map said “not built” when the truth was “built and unreachable”, and each was found by accident. This makes it a check.

A request can be addressed to a who
Fixed
The router was typed entirely by operation — a closed union of six verbs. “Bass player, play what you feel” names a musician and had nowhere to land, so it fell through to whichever operation happened to share a keyword. role and grantLevel now sit beside the verb rather than replacing it, and reading an address is deliberately narrow: live, “make the kick fatter” and “the bass is masking the kick” still route to operations
Three grants, each with a check that can fail
Working
A freedom level written into a prompt and never verified is a control that reports success while changing nothing — which this project has already shipped once. PLAY EXACTLY: same pitches, same count, onsets within 30 ms. PLAY AROUND IT: every source onset still has a note within 60 ms, anything may be added. PLAY WHAT YOU FEEL: one track, named bars, nothing outside. Every rule is shown refusing something — a shifted phrase, an added note, a dropped onset, a note in the wrong bar, a write to the wrong track
The tolerances are wall-clock, not ticks
Working
The same tick error is a different musical error at 70 BPM and at 170. Measured: the same 60-tick shift is refused at 40 BPM (187.5 ms) and allowed at 400 BPM (18.8 ms). This is also the quiet argument for symbolic takes — “did it keep my phrase?” is arithmetic on notes and guesswork on a waveform
Two players can never offer the engine swap

Where the leverage is

Layers 0 and 1 are complete, and Layer 2 has landed: the AUDITION sweep, clips on the timeline, and the song length itself are all recorded above. The timeline is no longer four bars long. What remains is ordered by value returned per unit of work, given what already exists on disk.

  1. A host, and the first real extract.

    Everything on our side of the seam is in place and tested without a network. What is left is not code: a machine with the pinned checkpoint and enough VRAM. Until one exists, the honest status of realization is “can be attempted, has not been” — and the app now says exactly that rather than showing a score.

  2. Work the reachability list down.

    Three off, 25 left. Transcription was a working model behind a broken call; the vault search was real ranking pointed at a catalogue nobody saw; the SoundFont engine was not an implementation at all. That is the lesson worth carrying: an unreachable file gets judged by its comments, because there is nothing else to judge it by, so each one has to be read before it is believed. What remains is mostly duplicates, and those are a different decision — delete, or mount and retire the one on screen.

  3. Turn on strict.

    Made concrete this pass: preservationScores became nullable and every unguarded read of it still typechecked, so the fabricated-number fixes had to be found by hand rather than by the gate. strictNullChecks is the difference between the compiler finding those and a person finding them.

What "verified" means here

Working means a live test drove the real app and observed real data changing — synthetic audio through Chromium's fake capture device, state read from React's committed fiber tree, cross-checked against the DOM. Decorative means the value shown is a literal in the source, or the control constructs no audio nodes when operated. Unplugged means a genuine implementation exists that no file imports. Not built means neither exists. Claims carried over from earlier passes were re-checked against the current branch rather than trusted.
