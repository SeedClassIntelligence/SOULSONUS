What "Working" means here — and what it used to miss

Every row below describes main at the commit named above, which is the commit Netlify builds. That distinction matters: for most of this project's life the map described a feature branch that had never been merged, so it reported components as working while the deployed site was white-screening on a missing import from before the audit began. The status of a room and the status of the site are different questions, and this map only answers the second one when the two are the same commit.

If the rows here disagree with what you see on the live site, check that first — git log --oneline -1 origin/main against the commit in the header. The stamp names the last code commit the rows describe; this document is committed immediately after it, so the deployed head is normally one commit further on and contains no code the map has not seen.

Under the DAW

E05 Realization

Not a room. The capability the Co-Producer and the DAW actions reach for
A seam, where there was a bill of materials
Fixed
ACE was registered, not integrated: seven manifest records naming repository URLs and a frozen commit, and no client, no endpoint invocation, no audio return path. There is now one interface — E05RealizationProvider — with the six task types, which of them lock output length to the source, and what each needs. A local host or a native backend plugs in behind it without a caller changing
The browser never addresses ACE
Working
Not a preference. ACE's own CORS policy admits only localhost origins, so a call from a deployed browser is refused before the model is consulted — which is exactly how the Demucs client failed, and it failed quietly. Requests go to a SoulSonus service route which holds the endpoint and the key server-side; source audio goes up as multipart, because we hold Blobs in a browser and not files on the inference host. Live: nothing in the served page names the host or the key
The old client could never have finished a job
Fixed
It compared ACE's status against the strings 'SUCCESS' and 'FAILED'. The server sends integers — 0 running, 1 succeeded, 2 failed — so a completed job would have polled until it timed out and then reported a timeout. No type could catch this; it is checked directly now, including that a status of "SUCCESS" is not read as done
Duration locking is carried in the contract
Working
Four of the six tasks return audio the same length as the audio sent in. That is timeline alignment for free, and it is the property that makes ACE usable from a sequencer at all, so it is named in the type rather than left as folklore: cover, repaint, extract and lego are duration-locked; text2music invents a length and must be placed deliberately

Where the leverage is

Layers 0 and 1 are complete, and Layer 2 has landed: the AUDITION sweep, clips on the timeline, and the song length itself are all recorded above. The timeline is no longer four bars long. What remains is ordered by value returned per unit of work, given what already exists on disk.

  1. A host, and the first real extract.

    Everything on our side of the seam is in place and tested without a network. What is left is not code: a machine with the pinned checkpoint and enough VRAM. Until one exists, the honest status of realization is “can be attempted, has not been” — and the app now says exactly that rather than showing a score.

  2. The Session Band role dimension.

    Instrument-specialist agents under the same governance the Co-Producer already uses. It needs a role dimension on the router and nothing from ACE, so it can start before a host exists.

  3. Turn on strict.

    The type gate now checks props, but strictNullChecks is still off, so an optional field read without a guard is invisible. That is the next tier of the same class of bug, and the same argument applies: it will surface a batch at once, which is a reason to schedule it rather than fold it into something else.

What "verified" means here

Working means a live test drove the real app and observed real data changing — synthetic audio through Chromium's fake capture device, state read from React's committed fiber tree, cross-checked against the DOM. Decorative means the value shown is a literal in the source, or the control constructs no audio nodes when operated. Unplugged means a genuine implementation exists that no file imports. Not built means neither exists. Claims carried over from earlier passes were re-checked against the current branch rather than trusted.
